# tell-scope

해석 가능한 AI 텍스트 탐지기 [DetectorScope](https://github.com/google-deepmind/detectorscope)로 글에서 "AI 티"가 나는 지점을 찾아 그 지점만 고쳐 쓰고 다시 채점하는 에이전트 스킬입니다. Claude Code, Codex처럼 `SKILL.md`를 읽는 에이전트에서 씁니다.

- **영어**: DetectorScope의 공개 오픈 도메인 탐지기를 그대로 씁니다.
- **한국어**: 공개 탐지기는 한국어에서 우연 수준(AUROC 0.39~0.53)이라, 같은 SAE 특징 위에 한국어 헤드(`heads/ko.json`)를 새로 학습했습니다. 실험적인 모델입니다.
- **규칙**: em dash, 가운뎃점, 이모지, 상투구("오늘날 빠르게 변화하는", "결론적으로", "delve" 등)는 탐지기와 별개로 규칙으로 찾습니다(`tells`). 탐지기가 놓치거나 학습 데이터에 없어서 오작동하는 부분입니다.

```
$ python scripts/score.py draft.txt 2>/dev/null
[{"lang": "ko", "label": "ai", "p_ai": 0.985, "gap": 4.008,
  "tells": [{"rule": "stock-phrase", "match": "오늘날", "line": "오늘날 빠르게 변화하는 IT 환경에서 …", "fix": "…"}, ...],
  "ai_features": [{"importance": 0.545, "description": "'결론적으로,' 요약 접속어",
                   "passages": ["...무리하며 / 결론[[적으로,]] 개발자의 생산성..."],
                   "hint": "…", "confidence": "high"}, ...],
  "human_features": [...]}]
```

에이전트는 `tells`를 먼저 고치고 AI 쪽 특징이 켜진 구간(`[[...]]`)만 손본 다음 다시 채점합니다. 절차는 [`SKILL.md`](SKILL.md)에 있습니다.

## 설치

NVIDIA GPU(6GB 이상 권장)가 있으면 빠릅니다. CPU로도 돌지만 글 하나에 1분 이상 걸립니다.

```bash
git clone https://github.com/yuyeol3/tell-scope && cd tell-scope
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cu126   # GPU. CPU면 생략
pip install -r requirements.txt
python -m pytest -q tests                                               # 모델 없이 도는 단위 테스트
```

처음 채점할 때 Hugging Face에서 탐지기(약 11GB, Gemma-2-2b 포함)를 받습니다. 한국어를 처음 채점할 때는 거기서 한국어 헤드에 필요한 부분만 잘라 `work/ko_model/`(약 3.8GB)에 저장합니다. 1~2분 걸리며 한 번만 합니다.

### 스킬로 등록

레포 폴더를 각 에이전트의 스킬 폴더에 연결합니다.

```bash
# macOS/Linux
ln -s "$PWD" ~/.claude/skills/tell-scope
ln -s "$PWD" ~/.codex/skills/tell-scope
```

```bat
:: Windows (관리자 권한 없이 되는 디렉터리 정션)
mklink /J %USERPROFILE%\.claude\skills\tell-scope %CD%
mklink /J %USERPROFILE%\.codex\skills\tell-scope %CD%
```

그다음 에이전트에게 "이 글 AI 티 빼줘"처럼 요청하면 됩니다.

## 채점기만 쓰기

```bash
python scripts/score.py a.txt b.txt          # 여러 파일을 한 번의 모델 로딩으로
python scripts/score.py draft.txt --lang ko  # 언어 지정 (기본은 자동 판별)
```

출력 필드는 `SKILL.md`의 표를 보세요. `gap`은 logit에서 임계값을 뺀 값이고 0 아래로 내려가야 사람으로 판정됩니다.

## 속도

RTX 4050 Laptop(6GB)에서 잰 결과입니다.

| | 로딩 | 900토큰 한국어 글 1편 | GPU 메모리 |
|---|---|---|---|
| CPU (fp32) | 52초 | 72초 | |
| GPU, 원본 탐지기 그대로 | 55초 | 16초 | 7.5GB (VRAM이 넘쳐 시스템 메모리로) |
| GPU, 쓰지 않는 블록과 lm_head 제거 (`score.load`, 영어) | 40~55초 | 2~4초 | 6.1~6.6GB |
| GPU, 한국어 경량 모델 (`ko_model.py`) | **15~18초** | **0.1~0.2초** | **4.0GB** |

한국어 경량 모델은 헤드가 읽는 경로만 남깁니다. 가장 깊은 훅(layer 18 입력)보다 뒤의 Gemma 블록과 lm_head를 버리고 SAE는 헤드가 쓰는 특징의 인코더 열만 남깁니다(16,384열 × 3개 → 65열). 계산을 바꾸지 않으므로 원본 탐지기와 점수가 같습니다. 글 10편에서 logit 차이는 최대 5.7×10⁻⁷이었고 토큰별 활성 1,682개 중 켜짐과 꺼짐이 다른 것은 없었습니다.

## 한국어 헤드

### 만든 과정

1. **공개 탐지기는 한국어에서 동작하지 않습니다.** 나무위키 문단과 AI 블로그 글 40쌍에서 AUROC 0.53, 한국어 PR 설명 39쌍에서 0.39였습니다. 사람 글은 ChatGPT 이전(나무위키 2021년 3월 덤프, 2019~2022년 GitHub PR)에서 가져왔고 같은 내용을 Claude가 다시 쓰게 해서 AI 글을 만들었습니다.
2. **SAE 특징에는 한국어 신호가 남아 있습니다.** 처음 측정한 AUROC 1.0은 아티팩트였습니다. AI 글에만 `#` 제목이 있었고 GitHub 사람 글에만 CRLF 줄바꿈이 있었습니다. 그래서 양쪽 모두 마크다운과 줄바꿈을 정규화했고(`score.plain`) 채점할 때도 같은 정규화를 거칩니다.
3. **헤드 학습**: [KatFish](https://github.com/Shinwoo-Park/katfishnet)(ACL 2025)의 논설문과 논문 초록 1,149편(사람 글, 그리고 GPT-4o, Solar, Qwen2, Llama3.1이 쓴 글)으로 L1 로지스틱 회귀를 학습했습니다(`scripts/train_ko_head.py --max-layer 18`). 시는 넣으면 산문으로 옮겨 가는 성능이 떨어져서 제외했습니다. layer 8, 14, 18의 SAE만 써도 4개 층을 모두 쓸 때와 성능이 같거나 나아서(PR AUROC 0.85 → 0.87), 모델을 layer 18에서 자를 수 있게 했습니다. 특징은 65개입니다. 모든 문서의 첫 토큰에서 같은 값으로 켜지는 특징 2개는 문체와 무관해서 bias에 합쳤습니다.
4. **특징 설명**: 원래 설명은 영어 글로 만들고 검증한 것이라 한국어에서는 맞지 않았습니다(예: 한국어 글에서 "침대와 매트리스"). 그래서 각 특징이 가장 강하게 켜진 한국어 구간을 모으고(`scripts/ko_snippets.py`) Claude가 그 구간을 읽고 한국어 설명을 다시 썼습니다. 설명마다 `confidence`를 달았지만 DetectorScope처럼 설명이 맞는지 따로 검증하는 단계는 거치지 않았습니다.
5. **임계값**: KatFish의 AI 글(2024년 모델)은 요즘 모델의 글보다 티가 훨씬 강해서 KatFish 기준 임계값(+0.89)을 쓰면 Claude가 쓴 글 대부분이 사람으로 통과합니다. 그래서 임계값은 PR 쌍에서 Youden 기준으로 정한 +0.2이고 나무위키 쌍으로 따로 확인했습니다.

### 성능

학습에 쓰지 않은 한국어 쌍(AI 글은 모두 Claude가 썼습니다)으로 잰 결과입니다.

| | AUROC | 임계값 +0.2에서 AI 적중률 / 사람 오판률 |
|---|---|---|
| 나무위키 vs AI 블로그 글 (40쌍) | 0.97 | 0.82 / 0.03 |
| PR 설명 (39쌍) | 0.87 | 0.72 / 0.15 * |

\* 임계값을 이 데이터에서 정했으므로 낙관적인 값입니다.

비교를 위해 [KatFishNet](https://aclanthology.org/2025.acl-long.1030/)(쉼표 특징 5개, 공개된 구현)을 같은 데이터로 재 보니 KatFish로 학습한 경우 0.32와 0.57이었습니다. 쉼표 습관이 장르마다 반대로 나타나기 때문이었습니다.

### 예시와 실전 테스트

아래 두 실험은 이전 헤드(4개 층, 특징 87개)로 했습니다.

**한국어 PR 설명**: Claude가 쓴 PR 설명(합쇼체, "이를 해결하기 위해", "~것으로 기대됩니다", 템플릿 섹션)을 스킬 절차대로 3라운드 고쳐 쓴 결과입니다.

| 라운드 | 바꾼 것 | gap | 판정 (p_ai) |
|---|---|---|---|
| 0 | 원문 | +3.95 | AI (0.97) |
| 1 | 문두 연결어와 "기대됩니다" 맺음 제거, 목록을 명사형으로, 해요체 | +0.48 | AI (0.50) |
| 2 | "개요"와 "기대 효과" 섹션을 첫 문단에 합침 | +0.10 | AI (0.40) |
| 3 | 문장 끝을 개조식("~수정", "~덜 씀")으로 | −0.86 | 사람 (0.20) |

**블로그 실전 테스트**: Opus 서브에이전트가 AI 티가 잔뜩 나게 쓴 블로그 글을 이 대화 맥락이 없는 다른 Opus 에이전트가 `SKILL.md`만 보고 고쳤습니다. 어조(존댓말)를 유지하는 규칙 때문에 gap은 +4.28에서 +2.76까지만 내려갔고 판정은 AI 그대로였습니다. 더 나쁜 점은 이모지가 학습 데이터에 없어서 "드문 문자" 특징이 이모지를 사람 쪽으로 읽었고 그 바람에 이모지 소제목(🚀🎯📚)이 그대로 남았다는 것입니다. 이 실험 뒤에 규칙 검사(`tells`)를 추가하고 채점 입력에서 이모지를 빼고 테스트 에이전트가 지적한 `SKILL.md`의 허점(목표에 못 닿을 때 처리, 수정 비율 세는 법, 넓게 퍼진 특징, 최종본 고르기 등)을 고쳤습니다.

### 한계

- **존댓말 편향**: 이 헤드는 합쇼체('-습니다')와 해요체 문장 끝 자체를 AI 쪽으로 봅니다. 위 예시에서도 마지막 한 걸음은 개조식으로 바꿔서 넘었습니다. 학습 데이터에서 AI 글이 실제로 합쇼체를 훨씬 많이 쓰기 때문입니다(KatFish 논설문: 사람 45%, AI 88%. 초록: 사람 0%, AI 35%). 근거 있는 상관관계이긴 해도 합쇼체로 쓴 사람 글까지 AI 쪽으로 밀립니다. 자기소개서처럼 합쇼체가 필요한 글에서는 종결 어미 특징이 남을 수밖에 없고 스킬은 어조를 유지한 채 다른 특징만 고치도록 되어 있습니다.
- **같은 탐지기로만 확인**: 고친 글을 독립된 다른 탐지기로 다시 재 보지는 않았습니다. 점수가 내려간 것이 글이 사람다워졌다는 뜻인지 이 헤드의 허점을 파고든 것인지는 구분하지 못했습니다.
- 평가 데이터가 작고(79쌍) AI 글을 쓴 모델도 Claude 하나뿐입니다. 요즘 GPT 등 다른 모델의 글과, 공개된 사람 글이 없는 자기소개서에서는 확인하지 않았습니다.
- 나무위키 평가셋은 어조 차이로 부풀려졌을 수 있습니다. 사람 쪽은 백과사전체(합쇼체 2%)이고 AI 쪽은 블로그체(합쇼체 78%)입니다. 어조 차이가 작은 PR 평가셋(37% 대 59%)의 수치가 더 현실적입니다.
- KatFish의 사람 논설문은 초중고 학생 글이라 사람 쪽 특징 일부는 "어린 학생 문체"(띄어쓰기 실수, 긴 문장 등)를 담고 있습니다. 그래서 스킬은 사람 쪽 특징을 늘리지 않고 AI 쪽 특징만 줄입니다.
- 1024 토큰(한국어 약 1,500자)을 넘는 부분은 잘립니다. 긴 글은 나눠서 채점하세요.

## 주의

- 이 결과는 **탐지기 하나**의 판정입니다. 이 탐지기를 통과했다고 해서 다른 탐지기나 사람 독자도 통과한다는 뜻은 아닙니다.
- 탐지기는 사람이 쓴 글도 AI로 판정하는 등 틀립니다. 원 DetectorScope와 마찬가지로 개인에 대한 판단(학업 부정행위, 채용 등)에 쓰지 마세요.
- 이 도구의 목적은 본인 글의 문체를 다듬는 것입니다. 글의 내용과 사실은 바꾸지 않도록 설계했습니다.

## 라이선스와 출처

- 이 레포의 코드: Apache-2.0
- [DetectorScope](https://github.com/google-deepmind/detectorscope) 코드는 Apache-2.0이고 탐지기 모델은 CC-BY-4.0입니다(Dugan et al., EMNLP 2026). 함께 받는 Gemma-2-2b에는 [Gemma 이용 약관](https://ai.google.dev/gemma/terms)이 적용됩니다.
- `heads/ko.json`은 [KatFish](https://github.com/Shinwoo-Park/katfishnet)(Park et al., ACL 2025)로 학습했습니다. KatFish 레포에는 라이선스가 명시돼 있지 않아서 이 레포에는 데이터를 넣지 않았고 학습된 가중치와 설명만 넣었습니다.
- 스킬의 재작성 규칙은 DetectorScope의 feature-guided paraphrase 프롬프트(`scripts/prompts/adversarial/feat.txt`)를 참고했습니다.
